# EZQUOTE Japan

Quotation tool for Gladex Travel & Tours' Japan land packages. It replaces an
Excel workbook: agents pick cities, tours, transfers and hotels, and the system
produces a per-person selling rate for every room category plus copy-ready
quotation text.

**The source of truth for behaviour is the BRD.** Where the old workbook and the
BRD disagree, the BRD wins. Acceptance criteria are BRD section 14.1; the results
are in [docs/uat/UAT-report.md](docs/uat/UAT-report.md).

- **Stack:** React 19, Vite 8, TypeScript 6 (strict), Tailwind CSS 4,
  react-router 8, @tanstack/react-query 5, Radix primitives, Supabase JS 2
- **Backend:** Supabase — Postgres with Row Level Security, Auth, one Edge
  Function (Deno)
- **Hosting:** Cloudflare Pages (static), no server of our own
- **Node:** 22 or newer, enforced by `engines`
- **Version:** 1.0.0-pilot — see [CHANGELOG.md](CHANGELOG.md)

## Architecture in one paragraph

The browser talks to Supabase directly; there is no API layer of ours. That is
only safe because **the database owns pricing integrity**. When a quotation is
created, a trigger freezes every rate it could need into
`quotations.snapshot` — so the browser never sends a price, and a rate change
tomorrow cannot alter a quote sent today. Row Level Security on all 24 tables is
the authorisation layer; the UI hides buttons for convenience only.
[Full detail](docs/ARCHITECTURE.md).

## Folder structure

```
src/
  app/              Shell: router, layout, guards, dashboard, navigation
  components/ui/    Shared presentational components. No business logic.
  data/
    supabaseClient.ts   One client, created once
    database.types.ts   GENERATED by `npm run db:types` — never edit
    repositories/       All Supabase access, returning domain shapes
  domain/           Pure TypeScript: the business rules
    money, snapshot, tiers, rounding, rateEngine, duration, permissions
    rates/ content/ output/ agents/ quotation/ audit/ history/
  features/         One folder per feature: screens + react-query hooks
    auth/ quotations/ rates/ content/ agents/ history/ audit/
  lib/              Cross-cutting: env validation, cn, csv, buildInfo, greeting
scripts/
  seed/             One-time workbook import (FR-017 Phase 1)
  generate-headers.ts     Writes dist/_headers at build time
  check-build-secrets.ts  Fails the build if a secret reaches dist/
supabase/
  migrations/       SQL, applied in filename order
  functions/        invite-agents (Deno)
tests/
  db/               Postgres tests on PGlite, built from the migrations
  uat/              Engine-level UAT and the PD test-case runner
e2e/                Playwright: UAT scenarios, security, a11y, mobile, CSP
public/
  _redirects        SPA fallback for Cloudflare Pages
docs/               Everything in the table above
```

**Four layering rules**, enforced by ESLint where it can be:

1. **`domain/` imports nothing but `domain/` and zod.** No React, no Supabase, no
   `@/data`, `@/features` or `@/components` — the build fails. This is what lets
   the same pricing rules run in the browser, the seed script and the UAT suite.
2. **Only `data/repositories/` touches Supabase.** Repositories convert
   snake_case rows to domain types at the boundary.
3. **Components hold no business logic.** A rule that decides a price, a tier or
   an eligibility belongs in `domain/`.
4. **`database.types.ts` is generated.** Re-run `npm run db:types` after every
   migration.

## Prerequisites

- **Node 22+** — `node --version`
- **Git**
- **No global Supabase CLI.** Everything goes through `npx supabase`, so the

## Local setup

```bash
git clone <repo-url>
cd ezquote-japan
npm install
cp .env.example .env     # then fill it in
```

Ask the project owner for the two values. `.env` is gitignored and never
committed.

```bash
npm run db:login                              # once per machine
npx supabase link --project-ref <ref>         # the subdomain of your Supabase URL
npm run db:types                              # regenerate the types
npm run dev                                   # http://localhost:5173
```

The dashboard shows a Supabase connection badge. Green means your URL and key
reach the project; it pings `/auth/v1/health` and reads no tables.

### Environment variables

| Name                            | Used where                                                            | Reaches the browser?                 |
| ------------------------------- | --------------------------------------------------------------------- | ------------------------------------ |
| `VITE_SUPABASE_URL`             | `src/lib/env.ts`; also the CSP origin in `dist/_headers`              | **Yes** — and it must                |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | `src/lib/env.ts` → the Supabase client                                | **Yes** — by design; RLS is the gate |
| `NODE_VERSION`                  | Cloudflare Pages build only                                           | No                                   |
| `CF_PAGES_COMMIT_SHA`           | Set by Cloudflare; becomes the footer build stamp                     | Yes (just the SHA)                   |
| `SITE_URL`                      | **Supabase Edge Function secret.** Invite redirect + CORS origin      | No                                   |
| `SUPABASE_SERVICE_ROLE_KEY`     | Injected into the Edge runtime by Supabase. **Never set it yourself** | **Never**                            |
| `E2E_*`, in `.env.uat`          | Playwright UAT only — test-user credentials                           | No                                   |

Only `VITE_`-prefixed variables are inlined into the bundle. `src/lib/env.ts`
validates both at startup and **refuses to boot** if the key is a secret or
service-role key, so a mistake fails loudly instead of shipping a key that
bypasses RLS. `npm run check:build-secrets` is the second net, over `dist/`.

## Database workflow

Migrations live in `supabase/migrations/` and are applied **in filename order**.

```bash
npx supabase db push --linked --dry-run   # ALWAYS preview first
npx supabase db push --linked
npm run db:types                          # then commit the regenerated types
npm run db:test
```

> **The linked project is production.** Never push a migration that has not been
> reviewed, and **never edit a migration that has already been applied** — write
> a new one. [RUNBOOK §5](docs/RUNBOOK.md#5-apply-a-database-migration) has the
> full procedure, including the mandatory backup first.

Add every new migration filename to the list in `tests/db/harness.ts`, or
`npm run db:test` will silently test the old schema.

### What the schema enforces

Enforced by triggers and policies, not by the UI. Fighting these in application
code means the database rejects the write.

- **Roles.** `super_admin`, `product_development`, `admin` are _managers_.
  `sales_supervisor` reads their team's quotations; `sales_agent` only their own.
  Signed-out callers get nothing.
- **Rates are versioned:** `draft → published → inactive`. Publishing locks a
  version permanently. Agents never see drafts, and a version cannot be published
  without at least one group-size tier.
- **FX rates and markups are append-only** — `UPDATE` and `DELETE` are revoked at
  the privilege level. The newest row in effect wins.
- **Quotations snapshot their own rates.** `app.build_rate_snapshot()` runs in a
  `BEFORE INSERT` trigger, so the browser cannot fake pricing. A quotation may
  only reference services in its own snapshot. Agent, reference and snapshot are
  immutable afterwards.
- **Change Rate entries cannot be edited or deleted.** A correction is a reversal
  that exactly negates the original; both rows stay. A reversal of a reversal is
  refused.
- **Profiles are separate from logins**, matched by email on first sign-in. An
  unrecognised email gets an inactive profile for a manager to approve.
- **Every important change is written to `audit_log`** by trigger. Managers read
  it; nobody writes to it.

Helpers live in the private `app` schema, not exposed through the Data API, and
are `SECURITY DEFINER` with `search_path = ''` so policies can call them without
recursing. **A `SECURITY INVOKER` function must check permissions explicitly** —
RLS filters rather than errors, so a refused write would otherwise look like a
saved change.

## Testing

Four suites, with different jobs.

```bash
npm test                 # domain + UI + engine-level UAT  (Vitest)
npm run db:test          # Postgres, RLS, triggers, functions (PGlite)
npm run e2e              # Playwright
npm run uat              # all three
```

**1. Domain and UI — `src/**/*.test.ts(x)`.** Pure rules and components, two
Vitest projects (node and jsdom). Coverage thresholds apply to `src/domain/**`.

**2. Database — `tests/db/`.** Runs the real migrations against in-memory
Postgres (PGlite) and tests grants, RLS, triggers and functions as each role.
**The harness grants nothing itself** — the migrations must grant the API roles
what they need, or the suite would pass against privileges production does not
have.

**3. Engine-level UAT — `tests/uat/`.** One block per numeric BRD 14.1 scenario,
plus a runner over `docs/uat/pd-test-cases.csv` so Product Development can add
cases without touching code.

**4. End-to-end — `e2e/`.** Playwright against a **separate UAT Supabase
project**; it signs in, creates quotations and can deactivate a user.
`e2e/uat-env.ts` compares project refs and **refuses to run against
production**. Without `.env.uat` the browser specs skip themselves with a reason.

```bash
cp .env.uat.example .env.uat    # then fill in the UAT project and its test users
npm run e2e
```

Checking the security headers needs the build served the way Cloudflare serves
it:

```bash
npm run build
npm run preview:headers         # Wrangler on 4173, with _headers and _redirects
# in another terminal:
E2E_HEADERS_BASE_URL=http://127.0.0.1:4173 npx playwright test --project=headers
```

## Deployment

Cloudflare Pages builds on every push to `main` and gives every pull request a
preview URL. Build command `npm run build`, output `dist`, `NODE_VERSION=22`.

- `public/_redirects` — the SPA fallback. Existing files in `dist/` are matched
  first, so `/assets/*` are still served as themselves.
- `dist/_headers` — **generated** by `scripts/generate-headers.ts` from
  `VITE_SUPABASE_URL`, so the Content-Security-Policy always names the Supabase
  project the bundle actually talks to. Production and preview point at different
  projects, and a committed `_headers` would silently block one of them.
- `style-src` includes `'unsafe-inline'`, and only `style-src`: Radix positions
  its portals by writing `style` attributes at runtime, and CSP has no nonce for
  attribute styles. Scripts stay strict under `default-src 'self'`.

**Production and preview must point at different Supabase projects.** Preview
with production credentials would let anyone with a pull-request link write to
live data.

Everything else — creating the project, Auth URLs, the Edge Function secret,
backups, rollback, key rotation — is in **[docs/RUNBOOK.md](docs/RUNBOOK.md)**.

## Troubleshooting

**Prettier fails on files I did not touch, or every line looks changed.**
Line endings. Everything is LF, enforced by `.gitattributes`. Fix with:

```bash
git config core.autocrlf false
npx prettier --write .
```

**`fatal: Unable to create '.git/index.lock': File exists`**
A git process died. Check nothing is actually running (no editor mid-commit),
then delete it:

```bash
rm -f .git/index.lock
```

**`npm run db:types` produces an empty file or an error.**
You are not linked, or not logged in:

```bash
npm run db:login
npx supabase link --project-ref <ref>
npm run db:types
```

If the file is right but `tsc` disagrees, you probably added a migration without
adding it to `tests/db/harness.ts`.

**A CSP error in the console: `Refused to connect to https://xxx.supabase.co`.**
The `VITE_SUPABASE_URL` the bundle was built with is not the project it is
talking to. In Cloudflare, fix the variable **and redeploy** — the value is
compiled in, so changing it alone does nothing. Locally, rebuild:

```bash
npm run build && npm run preview:headers
```

**`npm run preview:headers` warns "Infinite loop detected in this rule and has
been ignored" about `_redirects`.**
Expected and harmless. Wrangler flags `/* /index.html 200` because
`/index.html` itself matches `/*`. Cloudflare Pages already falls back to
`index.html` for an unmatched path when there is no `404.html` — verified: a deep
route returns 200 with `_redirects` removed entirely. `e2e/csp.spec.ts` asserts
the outcome, so the behaviour is tested rather than assumed.

**An invite email never arrives.**
The built-in Supabase sender allows only a few emails per hour. Wait an hour and
resend; do not press the button repeatedly. **Custom SMTP is required before
inviting all 156 agents** —
[RUNBOOK §1.5](docs/RUNBOOK.md#15-email-sending-for-the-pilot).

**The app cannot connect at all, and nothing has changed.**
The free Supabase project **pauses after about 7 days of inactivity**. Restore it
from the dashboard; it takes a few minutes and loses nothing —
[RUNBOOK §2.1](docs/RUNBOOK.md#21-the-project-pauses-after-about-7-days-of-inactivity).

**Vitest says `Cannot read properties of undefined (reading 'config')`, or Vite
cannot resolve `@/...`.**
You are in Git Bash. Use PowerShell for npm commands.

**A build from Git Bash produces a broken bundle.** The build _succeeds_, which
is what makes this one nasty. The symptoms:

- the page dies with `TypeError: Cannot read properties of null (reading 'useEffect')`,
  because the chunks each ended up with their own copy of React
- the fonts 404 and the console says `Failed to decode downloaded font`, with a
  URL containing a literal drive letter like
  `url(../../../../C:/dev/.../inter-latin-wght-normal.woff2)`
- `dist/assets/` has no `inter-*.woff2` files at all

All one cause: Git Bash reports the drive letter lowercase (`c:\`), so Vite sees
two different paths for the same file. **Rebuild from PowerShell** and check that
`dist/assets/` contains the seven `inter-*.woff2` files before trusting a build.

**A permission error (`42501`) where the UI offered the action.**
The UI is more permissive than RLS. The database is right; fix the UI, or add the
policy deliberately. Check `docs/ARCHITECTURE.md` §5 for the intended matrix.

## Conventions

- **`npm run check` must pass before you commit.** Prettier (single quotes,
  semicolons, trailing commas, 100 columns) and ESLint are authoritative.
- Named exports only; no default exports.
- `verbatimModuleSyntax` is on, so type-only imports need `import type`.
- Strict TypeScript including `noUncheckedIndexedAccess` and
  `exactOptionalPropertyTypes`. **Narrow values rather than casting.**
- Comments explain **why**, not what. A comment restating the code is noise; one
  explaining a business rule or a non-obvious constraint is the point.
- All files are LF, enforced by `.gitattributes`.
- Commits are numbered by setup step: `Step N: <summary>`.

## Security notes

- **The publishable key is public by design.** It is in the bundle, and that is
  fine: it grants nothing on its own, because RLS evaluates the signed-in user's
  JWT. The key to protect is the **secret / service_role** key, which bypasses
  RLS entirely.
- **The service-role key exists in exactly one place:** the Supabase Edge
  runtime, injected by the platform. It is never set by hand, never in `.env`,
  never in GitHub, never in Cloudflare.
- **Three independent nets against leaking one:** `src/lib/env.ts` refuses to
  boot if `VITE_SUPABASE_PUBLISHABLE_KEY` is a secret or service-role key;
  `npm run check:build-secrets` fails if key material reaches `dist/`; and CI
  runs that scan on every push.
- **No production credentials in GitHub.** CI needs none — the database tests run
  on in-memory Postgres from the migrations. The `uat-e2e` workflow uses a
  GitHub Environment holding **UAT** credentials only, and both the workflow and
  `e2e/uat-env.ts` refuse to run if they point at the production ref.
- **Backups contain every agent's name and email.** Restricted company folder
  only. `backups/` is gitignored, but the rule is the point, not the ignore file.
- **`.env*` is never committed** (`.env.example` and `.env.uat.example` aside),
  and neither is the workbook or any seed output.
- **The UI is not a security boundary.** Hiding a button hides nothing. Every
  rule that matters is a policy, a grant or a trigger.
